## 1. 프로젝트 개요

### 1.1 서비스 목적
사회초년생 첫차 구매자를 대상으로, 7가지 개인 조건을 입력하면
현대/기아/제네시스 25개 차종 중 최적 차종을 추천해주는 ML 기반 웹서비스

### 1.2 타겟 사용자
- 사회초년생 (첫 차 구매 예정자)
- 월소득 150~800만원 범위
- 국산차(현대/기아/제네시스) 구매 희망

### 1.3 추천 차종 25개
| 브랜드 | 차종 |
|--------|------|
| 현대 | 아반떼(가솔린/하이브리드), 쏘나타(가솔린/하이브리드), 그랜저(가솔린/하이브리드), 코나(가솔린/전기), 산타페(가솔린/하이브리드), 팰리세이드(가솔린/하이브리드), 아이오닉6(전기) |
| 기아 | K5(가솔린/하이브리드), K8(가솔린/하이브리드), 셀토스(가솔린), 스포티지(가솔린/하이브리드/디젤), EV6(전기) |
| 제네시스 | G80(가솔린/전기), GV80(가솔린) |

### 1.4 입력 변수 (ML 피처) 7개
| 변수명 | 타입 | 범위/카테고리 |
|--------|------|--------------|
| 월소득 | 수치 | 150~800 (만원) |
| 초기투입자금 | 수치 | 100~5000 (만원) |
| 가족수 | 수치 | 1~7 (명) |
| 주용도 | 범주 | 출퇴근/레저/가족용/업무 |
| 연료타입 선호 | 범주 | 가솔린/하이브리드/전기/디젤/상관없음 |
| 운전경력 | 범주 | 1년미만/1~3년/3년이상 |
| 거주지역 | 범주 | 도심/지방 |

### 1.5 기술 스택
| 영역 | 기술 |
|------|------|
| ML | Python, scikit-learn, XGBoost, imbalanced-learn |
| 데이터 증강 | Gemini API (gemini-2.5-flash-lite) |

## 2. 데이터 파이프라인

### 2.1 STEP 1 — 룰 기반 합성데이터 생성
- **파일**: `data/synthetic_car_data.csv`
- **행수**: 2,880행
- **방법**: 7개 입력변수 조합에 대해 도메인 룰 기반으로 추천 차종 레이블 부여
- **라벨당 샘플**: 약 115행 (균등 분포)
- **컬럼**: 월소득, 초기자금, 가족수, 주용도, 연료선호, 운전경력, 거주지역, 추천차종

### 2.2 STEP 2 — LLM Augmentation (Gemini API)
- **파일**: `data/augmented_car_data.csv`
- **방법**: Label-conditioned prompting
- **사용 모델**: gemini-2.5-flash-lite (신규 API 키 필요)
- **생성량**: 라벨당 40개 × 25개 라벨 = 1,000개 목표
- **실제 결과**: 1,016행 생성 (유효율 100%)
- **최종 행수**: 2,880 + 1,016 = **3,896행**

#### LLM Augmentation 설계 원칙
| 원칙 | 구현 방법 |
|------|-----------|
| Label Fidelity | 각 차종 정보(가격대/특성) 프롬프트에 명시 |
| Diversity | 소득/자금 넓은 범위, 운전경력/가족수 균등 분포 지시 |
| 품질 검증 | validate_row()로 범위/카테고리 이상값 자동 필터링 |
| Rate Limit | API 호출 간 1.5초 sleep, 실패 시 최대 3회 재시도 |

#### 트러블슈팅 기록
| 문제 | 원인 | 해결 |
|------|------|------|
| API 키 Invalid | 키 미입력 (YOUR_API_KEY_HERE) | 실제 키 입력 |
| 404 NOT_FOUND | google-generativeai(구 SDK)에서 모델명 deprecated | google-genai(신 SDK)로 전환 |
| 404 gemini-1.5-flash | 해당 키에서 1.5 계열 미지원 | gemini-2.0-flash 시도 |
| 429 RESOURCE_EXHAUSTED limit:0 | GCP 프로젝트 키 (free tier 할당량 0) | AI Studio에서 새 프로젝트로 키 재발급 |
| 404 gemini-2.0-flash-lite | 신규 사용자에게 deprecated | gemini-2.5-flash-lite로 변경 |

## 3. ML 모델 개발

### 3.1 전처리 파이프라인
```
범주형 변수 → OrdinalEncoder (순서 있는 인코딩)
  - 운전경력: 1년미만(0) < 1~3년(1) < 3년이상(2)
  - 연료선호: 가솔린(0)/하이브리드(1)/전기(2)/디젤(3)/상관없음(4)

타겟 → LabelEncoder (25개 클래스)

클래스 불균형 → SMOTE (k_neighbors=5)
```

### 3.2 피처 엔지니어링 (누적)
| 피처명 | 계산식 | 도입 버전 | 목적 |
|--------|--------|-----------|------|
| 자금여력비 | 초기자금 / (월소득+1) | v1.5 | 가솔린/하이브리드 구분 |
| 월소득_구간 | pd.cut(월소득, [0,250,400,550,999]) | v1.5 | 소득 구간 비선형 반영 |
| 자금_구간 | pd.cut(초기자금, [0,500,1500,3000,9999]) | v1.5 | 자금 구간 비선형 반영 |
| 전기차가능 | (거주지역==도심) & (초기자금>3500) | v2 | EV 추천 가능 여부 |
| 대형차가능 | (초기자금>3000) & (가족수>=3) | v2 | 대형 SUV 적합 여부 |
| 하이브리드적합 | (월소득>350) & (주용도∈[출퇴근,가족용]) | v2 | 하이브리드 적합 여부 |
| 소형차적합 | (초기자금≤3200) & (월소득≤380) | v3 | 소형차 가격대 적합 |
| 중형차적합 | 2500≤초기자금≤5000 & 280≤월소득≤580 | v3 | 중형차 가격대 적합 |
| 대형SUV적합 | (초기자금≥3800) & (가족수≥3) | v3 | 대형 SUV 가격대 적합 |
| 프리미엄적합 | (초기자금≥5500) & (월소득≥500) | v3 | 제네시스 등 프리미엄 적합 |

### 3.3 모델 버전별 성능 비교

| 버전 | 구조 | 주요 변경 | 정확도 | 비고 |
|------|------|-----------|--------|------|
| **v1** | RF + XGBoost | 기본 7개 피처 | RF 71.36% / XGBoost **73.83%** | 최초 학습 |
| **v1.5** | RF + XGBoost + Ensemble | 피처 엔지니어링 3개 추가, RandomizedSearchCV(n_iter=20), Soft Voting | **76.17%** (Ensemble) | +2.34%p |
| **v2** | 2단계 (Stage1 계열 + Stage2 전체) | Stage1(계열 14class) 예측을 Stage2 feature로 추가, 도메인 피처 3개 추가 | Stage1 78.72% / Stage2 **78.21%** | +2.04%p |
| **v3** | 2단계 + 후처리 규칙 | 가격대 적합도 피처 4개, 연료선호 후처리, n_iter=30 | 진행 중 | 목표 80%+ |

```
subsample=0.7, n_estimators=200, min_child_weight=1,
max_depth=8, learning_rate=0.15, gamma=0.1, colsample_bytree=0.7
```

|------|------|--------|
| 1 | 연료선호 | 44.8% |
| 2 | 주용도 | 16.1% |
| 3 | 가족수 | 10.7% |
| 4 | 운전경력 | 8.4% |
| 5 | 월소득 | 7.7% |

> **인사이트**: 연료선호(44.8%)가 압도적 1위 → 연료 타입이 차종을 거의 결정
> 초기자금이 꼴찌인 이유: 합성데이터 특성상 룰 기반으로 생성되어 연료/용도에 비해 상대적으로 단순 반영

### 3.5 약점 라벨 분석

**지속적으로 낮은 F1 라벨 (v1 → v2 추이)**
| 라벨 | v1 F1 | v2 F1 | 문제 패턴 |
|------|--------|--------|-----------|
| 그랜저_가솔린 | 0.58 | 0.552 | 그랜저_하이브리드로 오분류 (recall 0.50) |
| 산타페_하이브리드 | 0.60 | 0.690 | 산타페_가솔린과 혼동 |
| K5_하이브리드 | — | 0.667 | K5_가솔린과 혼동 |
| 팰리세이드_가솔린 | — | 0.697 | 팰리세이드_하이브리드와 혼동 |

**근본 원인**: `연료선호 = "상관없음"` 입력 시 같은 계열 가솔린/하이브리드 구분 실패
→ 이 경우 소득/자금이 주요 판단 근거인데, 두 차종의 가격 차이(약 400~600만원)가 충분히 반영되지 않음

### 3.6 2단계 분류 설계 근거

```
[기존 단일 모델 문제]
아반떼_가솔린 vs 아반떼_하이브리드 → 25개 중 2개 선택 (어려움)

[2단계 분류 해결]
Stage 1: 아반떼 vs 쏘나타 vs 그랜저 vs ... (14개 계열)
         → 계열 선택은 가격대/크기/용도로 비교적 명확
Stage 2: 아반떼_가솔린 vs 아반떼_하이브리드
         → Stage1 계열 예측값을 feature로 추가하여 연료 결정에 집중
```

**Leakage 방지**: Stage2 훈련 시 Stage1의 train 예측에는 cross_val_predict 사용

### 3.7 후처리 규칙 (v3 신규)
```
연료선호 ≠ "상관없음" 인 경우:
  예측된 계열에서 해당 연료타입이 존재하면 → 강제 보정
  예) 연료선호="하이브리드", Stage2 예측="그랜저_가솔린"
      → 그랜저 계열에 하이브리드 있음 → "그랜저_하이브리드"로 보정
```
